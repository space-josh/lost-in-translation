# AGENTS.md

## Project

Lost in Translation

Subtitle:

Translating Technical Work into Shared Understanding

This repository contains a custom HTML presentation built specifically for Integrate's
Product & Engineering organization.

This is NOT a slide deck.

Treat it like a polished product.

The audience should feel like they are navigating a beautiful application,
not advancing PowerPoint slides.

---

# Primary Goal

Teach engineers, product managers, designers, QA engineers and DevSecOps engineers
how to better merchandise technical work.

Merchandising means:

Translating technical work into language that creates understanding,
alignment and informed decisions.

The presentation is NOT about marketing.

The presentation is NOT about politics.

The presentation is NOT about "selling."

It is about helping good ideas become understandable.

---

# Audience

Roles:

- Software Engineer
- Design Engineer
- QA Engineer
- DevSecOps Engineer
- Product Manager

Experience level:

Mixed.

Most attendees benefit from concrete examples and practical tools.

---

# Presentation Length

25–30 minutes

Structure:

Act I
Story / keynote

Act II
Framework

Act III
Workshop

---

# Guiding Principle

Every scene teaches ONE idea.

Never combine lessons.

If a slide teaches two concepts,
split it.

---

# Visual Philosophy

Presentation first.

Framework second.

Artwork supports the narrative.

UI supports the artwork.

Animation supports the UI.

Never reverse this order.

---

# Build Philosophy

Treat every scene like a production UI.

Think:

Apple Keynote

Linear

Stripe

Integrate

Never PowerPoint.

---

# Scene Quality Bar

Before approving any scene ask:

1.
Can anything be removed?

2.
Is typography readable from 20 feet?

3.
Does the illustration advance the story?

4.
Is there a single visual focal point?

5.
Would this look believable as a real product screen?

---

# Animation

Animation is restrained.

Use motion only to:

Reveal

Focus

Connect

Never animate because it "looks cool."

---

# Commander Acorn

Commander Acorn is the recurring guide.

He is never comic relief.

He is competent.

Curious.

Professional.

Quietly optimistic.

He appears only when his presence advances the narrative.

---

# Presentation Principles

One idea per scene.

Whitespace is valuable.

Typography carries hierarchy.

Illustration creates emotion.

UI creates clarity.

Motion creates understanding.

# Workshop

The workshop is collaborative.

Participants work in groups.

Commander Acorn acts as facilitator.

The workshop concludes with discussion.

Not grading.

---

# Closing Question

The presentation concludes with one question:

"What mission are you asking people to approve?"

Everything builds toward this.
