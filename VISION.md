# VISION.md

# Lost in Translation

Translating Technical Work into Shared Understanding

---

# Purpose

This project is intentionally different from a traditional presentation.

It should feel like a thoughtfully designed software product that happens
to tell a story.

Every decision should optimize for:

clarity

craftsmanship

understanding

delight

restraint

The audience should remember how the presentation felt just as much as
what it taught.

---

# The Problem

Engineers frequently do excellent work.

Organizations frequently make reasonable decisions.

The gap is often not competence.

The gap is translation.

People propose solutions before clearly describing:

the problem

the opportunity

the outcome

the impact

the value

Without shared understanding,
good work struggles to gain momentum.

---

# The Mission

Teach engineers how to merchandise technical work.

Merchandising means intentionally packaging technical work so other people
can understand it well enough to make informed decisions.

This is not marketing.

This is not persuasion.

This is not politics.

This is translation.

---

# Success

Someone leaving the room should think:

"I know how to explain my next technical proposal better."

Not:

"I know how to convince people."

Understanding comes first.

Momentum follows.

---

# Philosophy

Technical excellence deserves communication excellence.

Communication is engineering.

Translation is engineering.

Shared understanding is an engineering outcome.

---

# Design Philosophy

The presentation itself should model the lesson.

If we teach clarity,

the slides must be clear.

If we teach intentionality,

the visuals must be intentional.

If we teach momentum,

the story should naturally build momentum.

The medium demonstrates the message.

---

# Presentation Philosophy

This is not a collection of slides.

It is one continuous experience.

Every scene should feel like another screen in the same beautifully designed
mission system.

Transitions should feel like navigation.

Not slide advancement.

---

# Commander Acorn

Commander Acorn is not the hero.

The audience is.

Commander Acorn exists to model curiosity.

He notices.

He asks.

He clarifies.

He translates.

He helps others succeed.

He never steals attention.

# Momentum

Momentum is not excitement.

Treat the presentation like software.

# North Star

People should leave saying:

"That presentation made a complicated idea feel simple."

Not:

"That presentation had cool squirrel graphics."

That is the mission.
